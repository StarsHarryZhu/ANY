# AGENTS.md

## Role

`src/` holds the library source — the entry point [main.py](../main.py) sits at the repo root. Three layers: **loop layer** ([control_loop.py](control_loop.py) plus the built-in implementations of the three pluggable slots, [default_choosing.py](default_choosing.py) and [default_saver_loader.py](default_saver_loader.py), with the external prompt file [default_system_prompt.md](default_system_prompt.md)) → **wrapper layer** ([llm/](llm/)) → **protocol layer** ([llm/protocol.py](llm/protocol.py)); the **tool layer** ([tools/](tools/)) sits alongside and is driven by the loop. Calls only ever go one way: the loop layer knows only the protocol, importing no SDK and no concrete wrapper class.

## Constraints & protocols

- **`control_loop.py` carries no provider branch.** The loop knows only the protocol; every shape difference is the wrapper's job. `provider_meta` is forwarded to the session loader as an opaque dict — the `API`-kind comparison lives there, not in the loop.
- **The pickers' home is [default_choosing.py](default_choosing.py).** Don't reintroduce selection code into `control_loop.py`; the loop only calls `model_choose` / `reasoning_choose` through the slot and treats `None` as cancellation. The one exception is the tool preset picker, which stays with the tool layer ([tools/_tool_console.py](tools/_tool_console.py)): it selects a tool-layer thing, the loop does not know about tools, and adding it to this slot's contract would make every existing custom chooser fall back to the default.
- **The three slots are resolved once at the top of `control_loop`, through [utils.py](utils.py)'s `load_links` / `resolve_module` / `load_system_prompt`,** and each one degrades to its hardcoded default with one dim line — a broken `links.json` is never fatal (the defaults' own errors still propagate). The pointer file lives under [../configs/](../configs/), not here.
- **[configs/tools.json](../configs/tools.json) and [configs/presets/presets_dir.json](../configs/presets/presets_dir.json) are the tool layer's siblings of `links.json`**, read through [utils.py](utils.py)'s `load_tools` / `load_preset_files` with the same one-dim-line degradation and the same repo-root, CWD-relative path rule. `tools.json` is the tool table (module path -> class name) and the only source of tools; `presets_dir.json` lists the preset files on offer. The tool layer owns what they mean; the loop never sees them.
- **[configs/commands.json](../configs/commands.json) is the loop layer's own config** — command name (`/compact`) to tool name, read once at the top of `control_loop` through `utils.load_commands` with the same one-dim-line degradation as everything else. It is *not* a hole in the rule above: the loop still never opens `tools.json`, it only resolves a name it was handed into a call through `tool_run`. A broken or missing file means no commands, never a crash and never a command that was not written down.
- **Every shipped `.json` config carries a top-level `"version"`, and each file has its own format number** — `LINKS_FORMAT` / `TOOLS_FORMAT` / `COMMANDS_FORMAT` / `PRESETS_DIR_FORMAT` in [utils.py](utils.py), `PRESET_FORMAT` in the tool layer where preset documents are opened. They are deliberately *not* one shared number: changing one file's shape must not invalidate the others. `config_version_problem(version, expected)` is the only judgement — it returns a reason or `None`, and never prints and never raises, so each loader keeps printing its own single dim line and taking its own existing fallback. Two rules that are easy to get wrong: a **missing** `version` counts as a mismatch (treating it as v1 would misread every unstamped file the day the format really moves), and the check goes *after* the `is not a JSON object` branch and **returns immediately**, so one bad file still produces exactly one line. Bumping a format number and re-stamping the repo's copy of the file is a single change. [configs/api_keys.json](../configs/api_keys.json) is exempt — hand-written, gitignored, and with no built-in default to fall back to — and `SESSION_FORMAT` is a separate scheme for user data, never to be compared against these.
- **A line starting with `/` is parsed by the loop, and the loop is what runs it.** `_parse_command` splits the command token from the rest of the line; a command found in `commands.json` is executed there and then through `tools.tool_run` — the same entry point a model tool call uses, which is why the `[tool]` line is identical. The one exception is display: a tool that declares `NEEDS_CONTEXT` may have replaced the working set outright (`compact` does), and the JSON line it returns says nothing anyone wants to read, so the loop prints the **new context usage** in its place — estimated as the summary turn's output tokens minus its reasoning tokens, because the new working set is exactly that text. It is marked `~`: the fixed overhead (system prompt, tool definitions) and the summary prefix are not measurable from here, and the figure must not be "fixed" into the full-request number without measuring the real thing. `_print_context_usage` is the only writer of that line, for a command and the end of a turn alike. The summarize turn behind it is silent (`display=False`), so a bare `/compact` shows exactly one line and nothing else. If the command carries trailing text, the command itself prints **nothing** — that text becomes an ordinary user message, its reply appears as usual, and the usage line that follows is that turn's own *measured* one; the estimate exists only for the bare form, where nothing follows to measure. Never print both: two lines in a row read as two compactions. A command with no trailing text ends the turn (no model round trip); a command *with* text runs first and then sends the remaining text as an ordinary user message. A command that is **not** in the table is not an error: the line is rewritten to `user_command(<name>) <text>` and handed to the model, which can recognize a mistyped command and call the tool itself — every command is a registered tool, which is what makes that recovery work. A bare `/` is not a command at all and goes through verbatim.
- **Sessions are named, and the name is opaque to the loop.** `choose_session` (the session picker and the name prompt) is a member of the saver_loader slot — the loop only forwards the returned name back into `load_session` / `save_session` and never builds a path or knows the layout. Writes are atomic (a `.tmp` file then `os.replace`) and never happen on the cancel path, nor when the caller passed `context` explicitly. The exit save is deliberate: a turn interrupted mid-stream leaves a legal unanswered user message that is worth keeping. The store (`../sessions/`) is gitignored plaintext, and both lists it holds contain raw SDK blocks that go through `model_dump(mode="json")` — that is what keeps Anthropic thinking signatures replayable.
- **The loop keeps two histories, and they only diverge when something compacts.** `context` is the working set — the only thing ever sent to the model — and `messages` is the full conversation, append-only. Both get every user message, every assistant reply and every `tool_continuation()` envelope (the same dict object goes into both; nothing mutates a message afterwards). A `context`-aware tool rewrites `context` in place and never touches `messages`. `save_session(name, context, messages, model, effort, provider_meta)` writes both; **the extra `messages` parameter is a change to the saver_loader slot's member signature**, so a custom module has to take it. The store is `SESSION_FORMAT = 2`; a version-1 file is discarded to `.bak` on load rather than upgraded.
- **A resumed session is replayed through the wrapper, never by the loop.** The loop asks `llm.context_display(...)` for neutral rows and renders them itself in the live turn's own markers — `User:`, `Model:` + Markdown, and the dim `[tool] name(args) -> result` line. It inspects no provider block. It replays `messages`, not `context` — a compacted session would otherwise replay as a single summary — and only the last `HISTORY_REPLAY` (50) of them, with the header saying so; the cut can split a `tool_use`/`tool_result` pair, which the wrapper reports as `result=None` and the loop renders as `?`. The replay sits after the preset picker and immediately before the prompt, and fires only for a session that was loaded — a caller that passed `context` explicitly gets none.
- **`_run_stream` is the only place that talks to the stream**, and it is why `compact` can summarize by asking the model: it takes the tools list *and* a `display` flag as parameters, so the ordinary turn passes `tools.tool_define()` with `display=True`, and the summarizer passes `None` with `display=False` — a background turn that still drains the stream and still yields the finished response, but writes nothing to the terminal. The summary is machinery, not a reply: nobody asked for that text, and what the user wants from `/compact` is the new context size. It is not "result not shown" — the summary really does go into `context`, and it is readable in the session file. It also returns the response instead of falling through, because the tool-turn loop needs `tool_calls`, the status line needs `used_context`, and the command path needs the summary turn's token counts.
- **A Live is torn down before the next turn opens one.** Don't `console.input()` or `print` while a Live is running — a tool the loop runs mid-turn may open one of its own (that is what `complete` is: one plain streamed turn), which is safe only because the loop's Live is always stopped first.
- **A Ctrl-C that lands while the stream is being iterated never reaches `stream_complete`.** The interrupted response is dropped whole; the user half stays in `context` unanswered, which both providers tolerate. Don't add a drain. This now also covers the summarize turn: a Ctrl-C during it leaves `context` exactly as it was.
- **Keep the two `finally` blocks nested.**
- **The status line uses `used_context` in both of its slots** — never `total_tokens`.
- **`console` is the module-level singleton from [utils.py](utils.py); use it, don't build another.** It must keep `highlight=False`. **A one-line notice is `note(...)`, not `console.print(f"[dim]…[/dim]")`** — `note` renders through `Text`, which does not parse markup, and the strings it is handed are full of file content and user input (version numbers, bad entries, exception text, session names): one `[/dim]` inside a config file makes rich's parser raise `MarkupError`, turning the notice into the crash it was supposed to soften. The same applies to the few non-dim lines — a dynamic value goes in through `Text`/`Text.assemble`, never interpolated into a markup string.
- **The protocol in [llm/protocol.py](llm/protocol.py) holds the members both wrappers must implement** — `get_response` / `get_model_list` are the deliberate exclusions (see [llm/AGENTS.md](llm/AGENTS.md)). The two sides account for tokens differently, so read the docstrings before touching any token property.
- **[configs/api_keys.json](../configs/api_keys.json) is never committed, pasted, or used as an example.** Its shape is synced with the README schema and [main.py](../main.py).
- **No package has an `__init__.py`.** `src/`, `src/llm/` and `src/tools/` are PEP 420 namespace packages: keep new subpackages that way, and never rely on a package `__init__` for initialization.

## Directory

```
control_loop.py            The REPL loop: streaming render, tool turn, slash commands, usage line, session save/resume, resume replay
default_choosing.py        Built-in pickers (the choosing_module slot)
default_saver_loader.py    Built-in named-session store, atomic writes (the saver_loader_module slot)
default_system_prompt.md   Extra system-prompt text appended after the date line (empty by default)
utils.py                   Config/links/tools/commands/preset loading, slot resolution, the shared console, selectors
../configs/                Every .json config: links, tools, commands, presets, api_keys (schema in ../README.md)
llm/                       Protocol + the two provider wrappers (see llm/AGENTS.md)
tools/                     Tool registry and execution (see tools/AGENTS.md)
```

## Progress & goals

The loop runs end-to-end on the messages path — selection, streaming render, tool turn, the usage line, and session save/resume all work — and stays provider-agnostic by construction. The responses path shares the loop but has not been run live. Slot resolution, every fallback branch, and the save/load round trip were checked by hand. The resume replay is new: both wrappers' `context_display` were checked by hand against synthetic archives, but no resume has been replayed live yet.

The two-history split and `/compact` are newer still. What was checked by hand is the loop's own bookkeeping, driven by a scripted fake wrapper: the command paths (known, unknown, bare `/`, command-with-text), the model-triggered `compact` mid-turn, the `context`/`messages` divergence, the exit save, and the 50-row replay — plus `load_commands`'s every degradation branch and the save/load round trip at version 2. Nothing here has been run against a live endpoint yet, and the reasoning above the fold (whether a summary is good enough to continue from) cannot be checked that way at all.

The config version gate was walked by hand as a matrix: correct / missing / `2` / `true` / `1.0` / `"1"` / not-an-object / bad JSON / absent, for each of `load_links`, `load_tools`, `load_commands`, `load_preset_files` and the tool layer's preset reader — asserting one notice at most per file and the documented fallback each time, plus a run of the whole startup path against the shipped files asserting zero notices.

Goals:

- Decide `load_api_config`'s failure treatment. It is the only loader with no `except (OSError, UnicodeDecodeError, json.JSONDecodeError)` and the only file opened without `encoding="utf-8"`, so a hand-edited `api_keys.json` with a trailing comma tracebacks while its five siblings each degrade with one dim line. Either give it the siblings' treatment or record that a broken required config is meant to be loud.
- Keep the loop provider-agnostic as tools and providers are added — pressure to branch on the provider here means a wrapper method is missing.
- Confirm the streaming render on the responses path once that path is run live.
- Resume a session that ends in a tool turn against a live endpoint: replaying the stored blocks is the untested half of persistence.
- Run `/compact` against a live endpoint: the summarize turn is a second, nested use of `_run_stream` inside a tool call, and no endpoint has accepted it yet.
